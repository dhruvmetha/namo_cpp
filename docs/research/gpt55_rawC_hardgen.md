> Query C — HARD-INSTANCE GENERATION / CURRICULUM. Raw, unedited codex stdout.

Best answer: generate hard NAMO episodes by **preserving a known solution**, then mutate and mine around it; pure random scene generation is the wrong tool.

“Regret” below means: **a strong solver finds the solution cheaply, but your current ranker/random search burns many simulator calls**.

**Ranked Recommendation**
1. **ACCEL-style solution-preserving mutation + PLR/DCD hard buffer.** Start with solved 1-push/2-push seeds, mutate locally, forward-verify, score by simulator calls, keep hard solvable cases by easy/med/hard and 1push/2push.
2. **Constructive backward templates.** Build episodes from chosen setup-finish skeletons, but treat backward construction as a proposal only.
3. **Hindsight relabeling.** Mine every failed rollout for achieved object poses, reachable contact edges, and setup states.
4. **Teacher-student parameter sampling.** Useful once your generator has clean knobs.
5. **PAIRED/POET/self-play.** Interesting paper baselines, but heavier than your current need.

Backward generation is **viable only in the constructive sense**. Physical pushes are not reversible, so “simulate the solution backward” is not sound. The safe version is: design a candidate predecessor, run the real forward simulator, and keep it only if the intended push chain works and random/search cost is high.
