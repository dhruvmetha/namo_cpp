# Positive-only value learning — a curated literature map

**What this note is.** A focused map of how other fields handle *our exact bind*: we can **confirm a move leads to a solution** (a positive), but we can **never confirm a move leads nowhere** (that needs proving a negative — that no continuation ever works), so we hold confirmed positives plus a pile of "unknowns," and we must learn a value/ranker from that under long-horizon credit assignment and expensive simulation labels.

**How it relates to our other docs (extend, don't duplicate).** `horizon_q_related_work.md` is a *novelty/threat* audit of the Horizon-Q design (SAVE, Bejjani, C-Learning, HACMan, Where2Act, DeepCubeA, Stop-Regressing) — it argues our combination is new. `multipush_learning_primer.md` is a plain-language *model+scheme map* (spatial Q-maps, V, policy, world model; BC/DAgger/ExIt/offline-RL/TD-vs-MC) — it name-drops "PU learning" in one glossary line but never develops it. **This note is the missing third lens: the positive-only supervision through-line** — it develops PU learning, self-imitation, implicit-feedback ranking, one-class learning, and the "manufacture positives" tricks (HER) that the other two docs skip, and it defines each term rather than assuming it.

**Term, once:** a *negative label* here = a move we have **proven** cannot lead to any solution within budget; an *unknown* = a move we tried-or-could-try but haven't found a finish for. Our whole problem is that unknowns are cheap and negatives are (almost) impossible.

## Group A — Reinforcement learning

**Hindsight Experience Replay (HER) — turn a failure into a positive for the goal you *did* reach.** Andrychowicz et al., "Hindsight Experience Replay," NeurIPS 2017 (arXiv 1707.01495). If you aimed at goal A and landed at B, store the episode as a *success for B*, manufacturing positives out of failed attempts. **Maps to us:** it is the canonical "make positives from what you have" move — but it needs a *positional, relabelable* goal; our goal is a **global binary** ("region opened" / "robot-goal reachable"), so there is no achieved-goal B to relabel a useless push to. HER's trick doesn't directly fire *unless* we redefine goals per-region (open question, noted in the primer).

**Goal-conditioned RL / Universal Value Function Approximators (UVFA) — one value net that takes the goal as input.** Schaul, Horgan, Gregor, Silver, "Universal Value Function Approximators," ICML 2015. Learn V(s, g) or Q(s, a, g) so a single network generalizes across goals; the substrate HER relabels into. **Maps to us:** this is the family our "value of the state a move leads to" lives in; our budget-conditioned critic Q(s, a, H) is a UVFA where the "goal" is a remaining-push budget (see C-Learning in `horizon_q_related_work.md`).

**Expert Iteration / AlphaZero — a search generates its own training targets, then the improved net makes the next search cheaper.** Anthony, Tian, Barber, "Thinking Fast and Slow with Deep Learning and Tree Search" (ExIt), NeurIPS 2017 (arXiv 1705.08439); Silver et al., "A general reinforcement learning algorithm..." (AlphaZero), Science 2018. Search (slow, with a simulator) finds good moves and outcome values; the net is trained to predict them; the sharper net guides the next round. **Maps to us:** this **is** the skeleton of our converging approach (bootstrap a value from search-found finishes, iterate shallow→deep). Critical difference: AlphaZero's self-play returns a **signed** terminal (win *or loss*) — it gets confirmed negatives for free; **we never do.** So we are ExIt *minus the loss signal.*

**Temporal-difference learning / value iteration / learned admissible heuristics — propagate value backward from outcomes.** Sutton, "Learning to Predict by the Methods of Temporal Differences," 1988; Bellman value iteration; for search specifically, learned cost-to-go as an A*/GBFS leaf heuristic (DeepCubeA, Agostinelli et al., Nature MI 2019 — see `horizon_q_related_work.md`). **Maps to us:** we do the *Monte-Carlo* version — label = "did the search actually reach a finish from here," not a bootstrapped next-state estimate. The primer already argues (TD-or-not-TD, Fedus 2019) that at horizon 2–3 with binary outcomes MC targets are the right, stable choice; this note just situates it: **we deliberately use MC returns, not TD backups.**

**Self-imitation learning (SIL) — learn only from your own past *good* episodes.** Oh, Guo, Singh, Lee, "Self-Imitation Learning," ICML 2018 (arXiv 1806.05635); relatedly Self-Imitation Advantage Learning, AAMAS 2021. Store trajectories whose realized return beat the current estimate and imitate *those actions only* — positive-only reinforcement that drives exploration in sparse-reward tasks. **Maps to us:** this is the closest RL statement of our exact stance — *train on confirmed good experience, stay silent on the rest.* It is the RL cousin of our masked loss (grade only what you know) and a direct precedent that "positives-only + ignore the rest" is a legitimate, published learning signal, not a hack.

**Offline RL with sparse rewards — stitch value from a fixed dataset without confirmed negatives.** Kumar et al., CQL, NeurIPS 2020 (arXiv 2006.04779); Kostrikov et al., IQL, ICLR 2022 (arXiv 2110.06169); advantage-weighted variants (AWR/MARWIL). These fight *over*-estimation of unseen actions with pessimism. **Maps to us:** informative by **contrast** — their headache is being too optimistic about unknowns; ours is the mirror risk of being too *pessimistic* (treating an unknown as a dead-end). The primer's verdict holds: because we use MC search-returns and never bootstrap, the deadly-triad/pessimism machinery is not ours to manage — but the *false-negative* risk it hints at is exactly our open problem (below).

**Reward shaping vs value learning — inject prior guidance without corrupting the objective.** Ng, Harada, Russell, "Policy Invariance Under Reward Transformations" (potential-based shaping), ICML 1999. **Maps to us:** a warning, not a tool — the primer already notes hand-shaping misleads here (the best first push often moves the object *away* from the goal), so we learn the value from outcomes rather than shape a reward. Included so the map is complete: we are firmly in the *learn-the-value* camp, not the *shape-the-reward* camp.

## Group B — Learning-to-rank / information retrieval / recommenders (the purest positive-only analogs)

**Implicit-feedback ranking — a click is a positive; a non-click is *not* a negative.** Rendle, Freudenthaler, Gantner, Schmidt-Thieme, "BPR: Bayesian Personalized Ranking from Implicit Feedback," UAI 2009; Pan et al., "One-Class Collaborative Filtering" (OCCF), ICDM 2008; Hu, Koren, Volinsky, "Collaborative Filtering for Implicit Feedback Datasets" (WRMF), ICDM 2008. The field's founding realization: you observe *what users engaged with* (positives) but a non-engagement mixes "disliked" with "never saw it" — you can't call it negative. BPR ranks observed-above-unobserved as *pairwise preference*; WRMF down-weights the confidence of un-observed entries instead of labeling them 0. **Maps to us — this is the tightest structural analog.** A *click ≈ a confirmed solving move*; a *non-click ≈ our unknown*. Their two fixes are exactly our two live options: **BPR-style pairwise** (rank a confirmed positive above an untried candidate, no absolute negative needed) and **WRMF-style confidence weighting** (train on unknowns but at low confidence) — either is a principled alternative to hard-masking the unknowns.

**Counterfactual / unbiased learning-to-rank — correct for *why* you never saw the negative.** Joachims, Swaminathan, Schnabel, "Unbiased Learning-to-Rank with Biased Feedback," WSDM 2017. A non-click can mean "irrelevant" or "never examined" (position bias); they reweight observed clicks by inverse propensity (how likely the item was to be *seen*) to get an unbiased ranking objective from biased positive-only logs. **Maps to us:** the deeper lesson — an *absent positive is not evidence of a negative, it's evidence of limited looking.* Our "we didn't find a finish" is precisely a look-limited absence; if we ever want to *use* unknowns as soft-negatives, propensity-style reweighting (weight by how hard we actually searched) is the principled way, not treating unsearched = dead.

**Positive-Unlabeled (PU) learning — the formal theory of learning a classifier from positives + unlabeled only.** Elkan & Noto, "Learning Classifiers from Only Positive and Unlabeled Data," KDD 2008; du Plessis, Niu, Sugiyama, unbiased PU risk, NeurIPS 2014 + convex formulation ICML 2015; Kiryo et al., "Positive-Unlabeled Learning with Non-Negative Risk Estimator" (nnPU), NeurIPS 2017; survey: **Bekker & Davis, "Learning from Positive and Unlabeled Data: A Survey," Machine Learning 2020 (arXiv 1811.04820)** — read this one first. Core result: if you know (or estimate) the *class prior* (the fraction of unlabeled that are secretly positive), you can build an **unbiased** risk estimator and train a real classifier without a single labeled negative. nnPU adds a non-negativity clamp so deep nets don't overfit the correction. **Maps to us — this is the formal name for our whole predicament.** Our masked loss is the *conservative degenerate case* of PU (ignore all unlabeled → zero use of the unknown pile); PU-proper says we could *recover signal from the unknowns* if we estimate the prior "what fraction of untried pushes are actually solvable within budget." That is an unexploited lever, with a caveat: PU's clean theory assumes labels are Selected Completely At Random (SCAR), and our positives are **model-selected** (we tried the moves the current model liked) — the SCAR violation is real and is where the Bekker-Davis "beyond SCAR" (ECML-PKDD 2019) line becomes relevant.

**One-class classification / anomaly detection — model the positives' region, flag everything else as "not that."** Schölkopf et al., one-class SVM, 2001; Ruff et al., "Deep One-Class Classification" (Deep SVDD), ICML 2018. Learn a boundary around the positive class from positives alone; no negatives required. **Maps to us:** a *weaker* framing than PU/ranking — it gives "looks like a solving state / doesn't" without a graded value, so it under-uses our confirmed-outcome structure. Worth knowing as the floor; PU and implicit-feedback ranking dominate it for us because they yield a *ranking*, which is what search consumes.

## Group C — Planning / TAMP / robotics (positive-only in a search loop)

**Learned heuristics for classical planning — fit cost-to-go from solved instances, use it to guide search.** Ferber, Helmert, Hoffmann, neural-net heuristics for classical planning, ECAI 2020 + bootstrapping version AAAI 2022; Shen, Trevizan, Thiébaux, "Learning Domain-Independent Heuristics" (STRIPS-HGN), ICAPS 2020. Generate (state, cost-to-goal) pairs from solved problems, train a net to predict cost-to-goal, plug in as the A*/GBFS heuristic; the AAAI-2022 "bootstrapping" variant grows from easy to hard instances. **Maps to us:** the planning-side precedent for our exact loop — **supervised value from solved runs → guide search → bootstrap easy-to-hard** — and confirmation that "learn the heuristic from successes and search with it" is a mature, working recipe outside robotics.

**Learned value/feasibility to guide TAMP search — prune or rank branches with a learned oracle.** Wells et al., learned feasibility for TAMP (order-of-magnitude planner speedups); Bejjani et al., "Receding-Horizon... Learned Value Function," Humanoids 2018 (arXiv 1803.08100, already the closest-domain neighbor in `horizon_q_related_work.md`); Kim, Kaelbling, Lozano-Pérez, learning to guide TAMP search. **Maps to us:** direct lineage — a learned value guiding a physics-sim push search — the difference our other doc already logs (unconditional value, no budget, no reactive-vs-search curve). Named here so the positive-only map is complete; detail lives in the threat audit.

**Learning from successful demonstrations only — imitate positives, no negative examples.** Behavior cloning from success (primer's BC discussion), and the imitation-of-own-success line that self-imitation formalizes. **Maps to us:** the imitation framing of positive-only; the primer already argues top-k of our Q-map *is* the policy, so we don't clone a separate policy — but it anchors that "successes-only supervision" is standard in robot learning.

**NAMO-specific learned search — the immediate neighbors in our own problem.** Stilman & Kuffner's classic NAMO (search over which obstacle to move, no learning); Scholz, Levihn, Isbell, Christensen, "NAMO with Learned Dynamic Constraints," IROS 2016 (learn object dynamics, not a search value); more recently a deep-RL *local* NAMO (A2C, IROS-era) and NAMO-LLM (arXiv 2505.04141, LLM-biased sampling of which obstacle to move). **Maps to us:** no existing NAMO work learns a **positive-only value/ranker to guide the which-push search** — the learned-NAMO papers learn *dynamics* or use an *LLM prior* or do *model-free local RL*. Our niche (a learned, bootstrapped, positive-only push-value guiding best-first search over expensive sims) is empty in the NAMO literature specifically.

## Closest fits — read these first (shortlist)

1. **Bekker & Davis, PU-learning survey (Machine Learning 2020, arXiv 1811.04820)** — the formal theory of exactly "positives + unlabeled, no negatives," including the *class-prior* lever we're currently leaving on the table by masking, and the *SCAR / beyond-SCAR* caveat that matches our model-selected positives.
2. **BPR + OCCF/WRMF (Rendle UAI 2009; Pan ICDM 2008; Hu-Koren-Volinsky ICDM 2008)** — the tightest structural analog: click=positive, non-click≠negative is *our* confirmed-solve=positive, unknown≠dead-end, and they hand us two ready alternatives to masking (pairwise ranking; confidence-weighting).
3. **Expert Iteration / AlphaZero (Anthony NeurIPS 2017; Silver Science 2018)** — the closest analog to the *whole loop* (search makes targets → bootstrap → iterate), with the one instructive gap that they get confirmed negatives (losses) and we don't.
4. **Self-Imitation Learning (Oh et al., ICML 2018)** — the RL statement of "learn from your own confirmed successes, stay silent on the rest," i.e. the principled cousin of our masked-loss/positive-only choice.
5. **Ferber et al. learned planning heuristics + bootstrapping (ECAI 2020 / AAAI 2022)** — the planning-side proof that "supervised value from solved runs, guide search, grow easy→hard" is a mature working recipe, transferable to us.

## What's genuinely novel about our combo vs what's solved

**Each *ingredient* is solved and standard.** Value-from-search-targets + bootstrap + iterate = ExIt/AlphaZero (Group A). Learn a heuristic from solved instances and grow easy→hard = Ferber/STRIPS-HGN (Group C). Positive-only supervision with the unknowns down-weighted or ignored = PU learning / implicit-feedback ranking / self-imitation (Groups A,B). MC-not-TD targets at short horizon = settled (primer). Shallow one-step-lookahead deploy = every push case-study does depth 2–4. **So the converging approach is standard-and-safe piece by piece — none of it is a research gamble on its own.**

**The genuinely open/hard part is the *interaction* of three constraints that each prior escape-hatch removes:**

**(1) Positive-only *without* a relabel escape.** HER manufactures a positive by relabeling to the goal you reached — needs a positional goal; ours is a global binary, so HER doesn't fire. AlphaZero gets a confirmed loss from a terminal — our sim never hands us "no continuation ever works." PU learning gets an unbiased estimator from a *known class prior* under SCAR — but our positives are **model-selected** (we tried what the model liked), violating SCAR, and we don't know the prior "what fraction of states are solvable within budget." **Every clean fix in the literature relies on an escape hatch we structurally lack.**

**(2) The false-negative-under-bootstrap trap — the sharp edge.** When our search *fails* to find a finish from a setup move, we cannot tell "truly a dead-end" from "our search/model just wasn't good enough yet." If we bootstrap — let the current model guide search, then down-rank moves it failed to finish — we risk **self-reinforcing blind spots**: the model down-ranks a good setup, so search never revisits it, so it's never labeled positive, so the down-rank sticks. Offline RL's pessimism (CQL) actively pushes *toward* this failure for us; counterfactual LTR's propensity-reweighting is the *only* literature tool aimed squarely at "absence-of-positive ≠ negative, correct for how hard you looked," and it has not been applied to a bootstrapped physics-search value. **This is the load-bearing open question, and it is not off-the-shelf.**

**(3) Long-horizon credit under expensive labels compounds (1) and (2).** The value of an early "setup" push is defined by whether a *good continuation exists* — a downstream success we may not have found yet — so a false negative at depth-1 is really an un-found positive at depth-2+, and each label costs a ~1s physics rollout so we can't brute-force our way past it (the foundational no-exhaustive-GT constraint). **The novel object is therefore: a positive-only, bootstrapped, search-generated value for long-horizon manipulation under expensive sims, where the central difficulty is distinguishing an unsolvable state from an under-searched one *without ever confirming a negative and without being able to enumerate.*** That specific triple is not solved in any single line above — the closest tools (PU's prior estimation, counterfactual LTR's propensity correction, ExIt's iterate-and-improve) each address one leg and would have to be *combined and adapted* to cover all three. That combination is where the real research is.
