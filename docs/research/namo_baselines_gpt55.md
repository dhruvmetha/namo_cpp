# NAMO Comparison Baselines — Literature Search

**Source:** codex CLI, GPT-5.5 @ reasoning effort `xhigh`
**Date:** 2026-07-10
**Purpose:** Generated to find candidate COMPARISON BASELINES / closely-related methods for our NAMO learned-push-ranker problem (discrete push primitives, perfect free MuJoCo verifier, minimize simulator calls). GPT-5.5 is the search engine; content below is preserved verbatim.

---

Bottom line: the closest fair baselines are not full TAMP systems. They are **ways to order or propose pushes before calling MuJoCo**: hand geometry, one-step lookahead, learned value-guided search, sequence-feasibility ranking, and learned samplers.

I verified the main paper metadata where linked. One warning: I could not verify a canonical paper literally named **KAMO**; if you mean kinodynamic / movable-obstacle planning, the closest verified papers are Bejjani-style receding-horizon pushing and Saxena-style adaptive motion primitives.

**1. Classical / Heuristic NAMO**
- **CH movable-obstacle path planner** - Chen & Hwang, “Practical Path Planning among Movable Obstacles,” ICRA 1991, cited in NAMO survey refs. It plans paths that shove/push obstacles along a route. Relevant as the old “push stuff out of the corridor” heuristic. **Easy**: rank pushes by how much they move the object out of the current shortest-path corridor. ([link.springer.com](https://link.springer.com/chapter/10.1007/978-3-642-00312-7_37))
- **Stilman NAMO heuristic search** - Stilman & Kuffner, “Navigation Among Movable Obstacles: Real-Time Reasoning in Complex Environments,” IJHR 2005. Decomposes NAMO using reachable free-space structure and heuristic search. Relevant because your wavefront/reachability objective is very close in spirit. **Easy/Medium**: implement a no-learning score: reachable-area gain, path-shortening, and obstacle displacement away from bottleneck. ([ri.cmu.edu](https://www.ri.cmu.edu/pub_files/pub4/stilman_michael_2005_3/stilman_michael_2005_3.pdf))
- **Probabilistically complete AMO planner** - van den Berg, Stilman, Kuffner, Lin, Manocha, “Path Planning among Movable Obstacles: A Probabilistically Complete Approach,” WAFR VIII / Springer 2009. Decouples robot path planning and obstacle moves. Relevant as a completeness-oriented planner, not a ranker. **Hard**: too much machinery for your one-object discrete-push setup; better cite than implement. ([link.springer.com](https://link.springer.com/chapter/10.1007/978-3-642-00312-7_37))
- **Physics-based adaptive motion primitives** - Saxena, Saleem, Likhachev, “Manipulation Planning Among Movable Obstacles Using Physics-Based Adaptive Motion Primitives,” ICRA 2021. Uses restricted physics-checked primitives plus multi-heuristic search to reduce simulator calls. Very relevant: expensive physics verifier, search, nonprehensile contact. **Medium**: port their idea as hand-designed primitive classes / heuristic queues over your existing push grid. ([arxiv.org](https://arxiv.org/abs/2102.04324))

**2. Learned Heuristics Guiding Search**
- **Guided TAMP search** - Chitnis et al., “Guided Search for Task and Motion Plans Using Learned Heuristics,” ICRA 2016. Learns heuristics/samplers to guide high-level and low-level TAMP search. Relevant as “learning reduces expansions.” **Medium**: adapt as a learned priority over candidate pushes or push prefixes. ([people.eecs.berkeley.edu](https://people.eecs.berkeley.edu/~pabbeel/papers/2016-ICRA-tamp-learning.pdf))
- **Relational value for GTAMP** - Kim & Shimanuki, “Learning Value Functions with Relational State Representations for Guiding Task-and-Motion Planning,” CoRL/PMLR 2020. Learns GNN action-values from planning experience. Relevant because it is a learned value used only to guide a solver. **Medium**: build object/path/reachability graph features, train Q/ranker on solved traces. ([proceedings.mlr.press](https://proceedings.mlr.press/v100/kim20a.html))
- **GNN best-first stream expansion** - Khodeir, Agro, Shkurti, “Learning to Search in Task and Motion Planning with Streams,” RA-L 2023. Learns which symbolic facts/objects to expand first. Relevant as learned search ordering, not policy execution. **Medium/Hard**: concept maps cleanly, but streams are a mismatch; implement as graph-ranked push expansion instead. ([arxiv.org](https://arxiv.org/abs/2111.13144))
- **PIGINet plan-feasibility ranking** - Yang, Garrett, Lozano-Perez, Kaelbling, Fox, “Sequence-Based Plan Feasibility Prediction for Efficient TAMP,” RSS 2023. Scores high-level plans before costly refinement. Very relevant: rank candidate 1- or 2-push sequences before sim. **Medium**: enumerate push prefixes, encode scene+sequence, train binary feasible-within-budget classifier. ([arxiv.org](https://arxiv.org/abs/2211.01576))
- **DeepCubeA learned A*/GBFS heuristic** - Agostinelli et al., “Solving the Rubik’s Cube with Deep Reinforcement Learning and Search,” Nature Machine Intelligence 2019. Learns a value heuristic used by search. Relevant algorithmically, not robotics. **Medium**: train cost-to-go/rank value and use it as best-first priority. ([nature.com](https://www.nature.com/articles/s42256-019-0070-z))

**3. Learned Action Samplers / Generators**
- **CVAE motion-planning sampler** - Ichter, Harrison, Pavone, “Learning Sampling Distributions for Robot Motion Planning,” ICRA 2018. Learns non-uniform samples from demonstrations. Relevant as “propose likely useful actions, verifier checks them.” **Medium**: train CVAE over successful `(edge, depth)` or 2-push prefixes; sample top-K then MuJoCo-verify. ([arxiv.org](https://arxiv.org/abs/1709.05448))
- **Learned skill models + samplers** - Wang, Garrett, Kaelbling, Lozano-Perez, “Learning Compositional Models of Robot Skills for Task and Motion Planning,” IJRR 2020. Learns skill preconditions and continuous parameter samplers. Relevant if you frame each push as a skill with learned effectiveness. **Medium/Hard**: overkill unless you add continuous push parameters. ([arxiv.org](https://arxiv.org/abs/2006.06444))
- **Neuro-symbolic skills** - Silver, Athalye, Tenenbaum, Lozano-Perez, Kaelbling, “Learning Neuro-Symbolic Skills for Bilevel Planning,” CoRL 2022. Learns operators, samplers, and parameterized policies for TAMP. Relevant to learned preconditions and setup actions. **Hard**: needs symbolic abstraction; useful citation, heavy baseline. ([arxiv.org](https://arxiv.org/abs/2206.10680))
- **Diffusion-CCSP** - Yang et al., “Compositional Diffusion-Based Continuous Constraint Solvers,” CoRL 2023. Uses diffusion models to sample continuous constraint solutions for TAMP. Relevant as modern learned sampler. **Medium/Hard**: discretized pushes make CVAE easier; diffusion is mainly a stronger sampler baseline. ([arxiv.org](https://arxiv.org/abs/2309.00966))
- **DiMSam** - Fang et al., “DiMSam: Diffusion Models as Samplers for TAMP under Partial Observability,” arXiv 2023, revised 2024; venue not verified from source. Relevant as diffusion sampler inside TAMP. **Hard**: partial-observability machinery is unnecessary here. ([arxiv.org](https://arxiv.org/abs/2306.13196))

**4. Non-Myopic / Setup-Action Learning**
- **VPG push-grasp synergy** - Zeng et al., “Learning Synergies between Pushing and Grasping with Self-supervised Deep RL,” IROS 2018. Learns pushes that enable later grasps. Very relevant conceptually: setup move gets no immediate reward except future success. **Medium**: adapt reward from “future grasp succeeds” to “future push opens goal.” ([arxiv.org](https://arxiv.org/abs/1803.09956))
- **Visual Foresight Trees** - Huang, Han, Yu, Boularias, “Visual Foresight Trees for Object Retrieval from Clutter with Nonprehensile Rearrangement,” RA-L 2021/2022. Uses learned forward prediction plus tree search for push sequences. Relevant to explicit multi-step push planning. **Hard** if learning dynamics; **Medium** if you replace learned dynamics with MuJoCo and only copy the tree policy. ([arxiv.org](https://arxiv.org/abs/2105.02857))
- **Learned symbolic operators** - Silver, Chitnis, Tenenbaum, Kaelbling, Lozano-Perez, “Learning Symbolic Operators for Task and Motion Planning,” IROS 2021. Learns preconditions/effects for planning. Relevant to recognizing “this push creates the precondition for the finish push.” **Hard**: needs invented predicates like `opens_contact_edge` or `moves_blocker_from_bottleneck`. ([arxiv.org](https://arxiv.org/abs/2103.00589))
- **PIGINet sequence feasibility** - same Yang et al. RSS 2023 above. Relevant because setup is naturally judged at sequence level, not one action. **Medium**: probably the cleanest non-myopic learned baseline. ([arxiv.org](https://arxiv.org/abs/2211.01576))

**5. Simulator / Verifier in the Loop**
- **SAVE** - Hamrick et al., “Combining Q-Learning and Search with Amortized Value Estimates,” ICLR 2020. Learned Q prior guides MCTS; search improves targets. Very relevant algorithmically: learned value plus small search budgets. **Medium**: implement MCTS/best-first over your discrete pushes; train from search-improved labels. ([arxiv.org](https://arxiv.org/abs/1912.02807))
- **Expert Iteration** - Anthony, Tian, Barber, “Thinking Fast and Slow with Deep Learning and Tree Search,” arXiv 2017. Tree search produces better policies; network amortizes them. Relevant training loop for your perfect verifier. **Medium/Hard**: self-play becomes self-search over NAMO episodes. ([arxiv.org](https://arxiv.org/abs/1705.08439))
- **AlphaZero-style policy/value + MCTS** - Silver et al., “Mastering Chess and Shogi by Self-Play with a General RL Algorithm,” arXiv 2017 / Science 2018 line. Relevant as the canonical policy/value/search loop. **Hard**: too much RL infrastructure; cite, but SAVE/ExIt are cleaner baselines. ([arxiv.org](https://arxiv.org/abs/1712.01815))
- **MCTS rearrangement** - Labbé et al., “Monte-Carlo Tree Search for Efficient Visually Guided Rearrangement Planning,” RA-L 2020. Uses MCTS for object rearrangement. Relevant as search over rearrangement actions. **Medium**: replace their action model with your push grid and MuJoCo verifier. ([arxiv.org](https://arxiv.org/abs/1904.10348))
- **Bejjani RHP value search** - Bejjani, Papallas, Leonetti, Dogar, “Planning with a Receding Horizon for Manipulation in Clutter using a Learned Value Function,” arXiv 2018; venue not verified from source. Closest manipulation-domain learned value + short search. **Medium**: train Q from solved plans and use it as a leaf/ordering heuristic. ([arxiv.org](https://arxiv.org/abs/1803.08100))

**6. Learned Push / Nonprehensile Planning**
- **Probabilistic push dynamics** - Bauza & Rodriguez, “A Probabilistic Data-Driven Model for Planar Pushing,” ICRA 2017. Learns push outcome distributions. Relevant only if replacing MuJoCo; you do not need that. **Hard / low value** as baseline. ([arxiv.org](https://arxiv.org/abs/1704.03033))
- **Data-efficient pushing MPC** - Bauza, Hogan, Rodriguez, “A Data-Efficient Approach to Precise and Controlled Pushing,” CoRL 2018. Learns GP dynamics for controlled pushing. Relevant to pushing, not search ordering. **Hard / low value** for your exact claim. ([arxiv.org](https://arxiv.org/abs/1807.09904))
- **Push-Net** - Li, Lee, Hsu, “Push-Net: Deep Planar Pushing for Objects with Unknown Physical Properties,” RSS 2018. Predicts/replans pushing for unknown objects. Relevant as learned push policy/model. **Hard**: continuous visual pushing setup differs from discrete NAMO primitives. ([roboticsproceedings.org](https://www.roboticsproceedings.org/rss14/p24.html))
- **DIPN** - Huang, Han, Boularias, Yu, “DIPN: Deep Interaction Prediction Network with Application to Clutter Removal,” ICRA 2021. Predicts push outcomes in clutter. Relevant if learned dynamics were needed; here MuJoCo is exact. **Hard / not central**. ([arxiv.org](https://arxiv.org/abs/2011.04692))
- **HACMan** - Zhou, Jiang, Yang, Paxton, Held, “HACMan: Learning Hybrid Actor-Critic Maps for 6D Non-Prehensile Manipulation,” CoRL 2023. Spatial contact-location critic for nonprehensile manipulation. Very relevant architecture-wise. **Medium**: use a HACMan-style per-edge critic as a learned ranker baseline. ([arxiv.org](https://arxiv.org/abs/2305.03942))
- **HACMan++** - Jiang, Wu, Zhou, Paxton, Held, “HACMan++: Spatially-Grounded Motion Primitives for Manipulation,” arXiv 2024; RSS 2024 indicated by project URL, not verified from source text. Relevant to primitive choice + contact grounding + multi-step chaining. **Medium/Hard**: useful if you compare against a policy, less direct than a ranker. ([arxiv.org](https://arxiv.org/abs/2407.08585))

**Shortlist**
1. **Hand-designed NAMO geometric ranker** - CH/Stilman-inspired. This is the baseline a reviewer will expect: no learning, just “push the blocker out of the corridor / maximize reachability gain.” Implement by scoring each candidate push with geometry-only features before sim.

2. **One-step immediate-opening / reachability-gain lookahead** - Be explicit that it is myopic. It should be strong on 1-push and weak on setup pushes, which makes it the cleanest test of your non-myopic claim. Implement by simulating candidates until one opens, or by using it as a costed curve where those simulator calls count.

3. **Bejjani/SAVE-style learned Q-guided best-first search**. This is the closest learned-search baseline: value/ranker guides a real verifier-backed search. Implement with your existing push grid, same training traces, and compare simulator calls to solution.

4. **PIGINet-style sequence-feasibility classifier**. This directly attacks the setup-move issue by scoring 2-push prefixes, not isolated first pushes. Implement by generating candidate `(push1, push2)` prefixes from training searches and training a binary “sequence solves” scorer.

5. **CVAE / diffusion action sampler**. This is the best “sampler not ranker” comparison: generate a small top-K set of promising pushes, then let MuJoCo verify. Implement CVAE first; diffusion only if you need a stronger modern sampler.

**Gap**
Your exact setup is underexplored. Most prior work differs on at least one key axis: it learns dynamics instead of using a perfect simulator, samples continuous grasps/placements instead of ranking a fixed discrete push grid, optimizes task success instead of simulator calls, or handles multi-object rearrangement rather than one blocking object with a 1-2 push setup/finish structure.
