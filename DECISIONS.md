# Faithful MORE port: decisions

This branch replaces the MORE port audited on 2026-11-24 (`python/namo/planners/opening/more_mcts.py` at 13763e54, removed here) with MORE's own search code run behind an adapter, and fixes the training code. "Row N" refers to the component table in `/common/users/dm1487/scratch_namo/more_audit_20261124/SPEC.md`. MORE means Huang, Guo, Boularias, Yu, ICRA 2022 (arXiv 2202.01426v3) and github.com/arc-l/more at 70402c0. When the paper and the code disagree, the code decides behaviour and the paper decides intent.

## Decided before implementation [USER via coordinator, 2026-11-24]

**D1. Vendor MORE's search, do not copy it.** `mcts/nodes.py`, `mcts/search.py`, `mcts_network/nodes.py`, `mcts_network/search.py` and `constants.py` are imported unmodified at runtime from the pinned clone (`python/namo/planners/opening/more_vendor.py:75-113`). The clone is `$MORE_REF`, default `$NAMO_SCRATCH/reference/arc-l_more`; `load_more` refuses any HEAD other than 70402c0 and any local edit to those five files (`more_vendor.py:58-65`). The repo has no LICENSE file, so nothing of theirs is committed here. Our side is the adapter only: `NamoMove` (their PushMove), `MoreContext` (their MCTSHelper), `NamoPushState` (their PushState), each citing the line it replaces. None of the five files has a PyBullet import, so every piece imported; nothing was stopped. Rows 1-5, 8, 11-14, 36-40.

**D2. One display-only runtime change.** Their search loops are wrapped in `tqdm` (mcts/search.py:11, mcts_network/search.py:12). The adapter rebinds that module name to a disabled tqdm unless `MORE_TQDM=1` (`more_vendor.py:103-107`); a collection campaign runs millions of iterations. No logic is touched.

**D3. Collection follows MORE's semantics** (decision 2 of the audit, rows 6, 7, 9, 17). `collect_episode` (`more_vendor.py:420-473`) runs their UCT `best_action(300, -1, eval=False)` (paper IV-B; constants.py:42 "300 for collection data"; mcts_main.py:354, :483 `test` False), saves every tree as `save_mcts_data` does (mcts_main.py:180-212; `tree_rows`, `more_vendor.py:373-393`), executes `best_child_top`, resets the caches (mcts_main.py:561) and searches again from the executed state until the push opens or hmax pushes are executed. Terminal nodes are re-selected and every selection adds a visit, as in their code; visit counts are the loss weights (dataset.py:191). The executed push reuses the tree's cached transition, so it costs no call (MORE executes it on a separate real env, mcts_main.py:507-519). Every `env.step` is counted per search and per episode (`calls`, `searches[i].calls`), so a SPAR-matched budget can be set by episode count.

**D4. Tie order is whatever their code produces.** Their children are popped from the end of the action list (mcts/nodes.py:52, mcts_network/nodes.py:56) and `np.argmax` takes the first maximum. Our action list is sorted by (object, edge, depth) before it reaches them (`more_vendor.py:203`), so the order is independent of the prior, as MORE's contour sampling is independent of its network. Rows 3, 39.

**D5. Training fixes BUG-6 to BUG-9 in our code.**
- No rows for untried actions: the collection tree has none (D3), the H5 marks only rows as evidence (`scripts/rl_loop/more_build_h5.py`), and both trainers train only evidence cells (`train_more.py` `MoreActionDataset`, `train_more_eca.py` `MoreBoardDataset`). Row 23.
- `contact_px` is (column, row) everywhere: `more_net.read_contact_values`, `more_training.rotate_pixel`, `train_more.paint`. Row 29.
- The per-sample rotation is each push's own direction, from edge e toward its mate e ^ 1 (`namo_push_controller.cpp:178-210, :258-260`; `more_training.push_angle`, `more_net.push_angles`), shared by trainer, scorer and verify. `python/tests/test_more_regressions.py::test_bug8_every_edge_points_right_after_the_training_rotation` checks all 60 edges point right. Row 28.
- `verify_more_net.py` scores only rooms both trainers exclude (`more_training.heldout_rooms`). Row 35.

**D6. The four approved substitutions and hmax 2 are kept.** Action library (`MoreContext.actions_for`), reachable goal-sample fraction for the grasp Q inside push_result (`NamoPushState.push_result`), verified opening for "graspable" (`is_push_over`, push_result ≥ max_q = 1.0 exactly when opened), simulator-call budget where wanted (`MoreBudgetExhausted`). Each search's `max_level` is the pushes still left in the episode. Jam-depth pruning stays as a consequence of the depth axis (row 16; `MoreContext.simulate`).

**D7. Deploy has two stopping modes** (`solve_scene_more`, `more_vendor.py:500-589`; `--more-stop-mode` in `scripts/sandbox/eval_bestfirst.py`, `more_stop_mode` per arm in `run_one_keyhole_frozen.py`). Rows 44-45.
- `protocol` (default): one MORE deploy search, stopped at the first verified opening anywhere, rollouts included, under the call cap. MORE's own early stop is off because ours replaces it. It also ends when no non-terminal node has an unsimulated child left (`exhausted`) or after `stall_iters` iterations with no call and no expansion (`stalled`): MORE's greedy selection never picks a sibling whose clamped prior is 0 while an expanded sibling scores above 0, so without this the loop would spin for free.
- `native`: more_main.py:393-525. Each decision runs `best_action(num_iter=50, -1, eval=True)` (MORE-50, MORE's stop rule), executes `best_child_top`, resets the caches and searches again; success is an executed push that opens; every search is charged, and so is executing a child the tree never simulated.

**D8. Our architecture inside MORE.** `scripts/rl_loop/train_more_eca.py` (a separate small trainer, not an option in `train_q2.py`) trains the Q2/HY5U EdgeCrossAttn (`namo.rl_loop.train_gen._make_network(value_bins=0)`, a scalar head) on MORE's labels with MORE's loss: target max(child.q), weight min(visits, 50), SmoothL1(β=0.8) × weight summed over cells and divided by the batch (lifelong_trainer.py:356-357). Its output is in MORE's units, so `--prior more_eca` (`more_scorer.MoreEcaScorer`) hands it to MORE's search raw; LiveScorer would have put a sigmoid on it (`live_scorer.py:206`). No fixed unit-conversion map was built. What does not carry over: MORE's per-action rotation and 3×3 painting exist because its head is a pixel map; EdgeCrossAttn already emits one value per (edge, depth), so a sample is a state with all its rows.

## Open with the user: configurable, PROVISIONAL defaults

**P1. Invalid-push negatives** (row 24): `--invalid ours|more` in both trainers, default `ours` (PROVISIONAL): an unreachable cell is its own sample at label −1, weight 1, at most 30 per state. `more` is MORE's dense negative (dataset.py:423-430): inside every sample, each unreachable cell of the same state is painted label 0 at weight 0.001, MORE's collision weight. MORE's 0.0001 "thin air" class has no counterpart: every contact in our library touches the object. (`python/namo/rl_loop/more_training.py`.)

**P2. Training schedule** (rows 33, 34): `--schedule ours|more`, default `ours` (PROVISIONAL), the pilot's recipe (`train_more.py`: SGD, 1000-step warmup, cosine T_0=2, clip 10; `train_more_eca.py`: train_q2.py's AdamW recipe). `more` is lifelong_trainer.py as written: batch 8, SGD(momentum 0.9, wd 2e-5), CosineAnnealingWarmRestarts(T_0=50, T_mult=2, η_min=1e-8) stepped per iteration in epoch 0 and once per later epoch, 51 epochs, no warmup (their warmup branch is `if epoch < 0`, dead), no clipping; then the fine-tune stage from the paper (IV-C) with the numbers left commented out at lifelong_trainer.py:36-41 (batch 28, lr 1e-5, T_0=20, 21 epochs), restarting the optimiser as their `--pretrained_model` run does (lifelong_trainer.py:261-263).

**D9. MORE's schedule on a budget-matched collection: same optimizer steps, more varied data** [CLAUDE, 2026-11-24, under the user's "use MORE's choices" default for P1 and P2]. The collection matched to SPAR's ~24.6M simulator calls has about 10M rows, 150 times MORE's 65,384 transitions ("243 training cases (65384 transitions in 30 hours with PyBullet)", paper IV-C; a transition is one simulated child, which is one saved row, mcts_main.py:180-212). Running `lifelong_trainer.py`'s 51 + 21 epochs over 10M rows would take weeks of GPU time, and MORE never trained that long: "Training on PPN on all data used around 22 hours". So both trainers take `--epoch-samples 65384`: each epoch draws 65,384 items from a fresh permutation, and everything else is `lifelong_trainer.py` (batch 8, SGD, CosineAnnealingWarmRestarts stepped per iteration in epoch 0 and per epoch after, 51 epochs, then the fine-tune stage). Optimizer steps and the learning-rate curve match MORE's step for step; each row is seen about 0.5 times instead of 72. MORE keeps no validation split and uses the last checkpoint of each stage: the fine-tune starts from `lifelong_model-50.pth` (README.md:81) and deploy loads `lifelong_model-20.pth` (ppn_main.py:334), the last of 51 and 21 epochs (lifelong_trainer.py:291-299 saves every second epoch and the last two). So the last checkpoint is the deployed one here too; the held-out rooms (`heldout_rooms`, 10%) are only scored afterwards by `verify_more_net.py`. For EdgeCrossAttn an item is a state with all its rows (about 5.8), so at equal steps it sees about 5.8 times as many labels as PushNet; that is the architecture's nature (D8), not a schedule change. `--epoch-samples 0` keeps full passes.

**D10. Budget cuts are prefixes of one ordered H5.** `more_cut.py` merges the shards, lets reruns of preempted workers replace the killed worker's partial last room, orders episodes by (shuffled manifest index, object), and cuts at room boundaries at each call budget. The H5 is built in parallel parts over consecutive episode chunks (`more_build_h5.py --episode-offset`) and joined by raw chunk copy (`more_merge_h5.py`), which stores each cut's state count as `cut_<label>_states`. A learning-curve run trains on that prefix (`--cut`); held-out rooms are drawn from the whole file, so every cut is validated on the same rooms.

## Smaller choices made here

**S1. Priors are passed raw.** The old `--more-prior-scale minmax` is gone. MORE clamps the prior to [0, 1.2] itself (mcts_network/nodes.py:117), so only a network trained in MORE's units (`--prior more`, PushNet; `--prior more_eca`) is a valid prior. A network whose outputs all exceed 1.2 ties at the clamp and MORE's first-max rule then picks the LAST action of its list.

**S2. An empty root.** If every root push fails, MORE's tree has no root child and `best_child_top` raises on `np.argmax([])` (mcts/nodes.py:129-132). `run_search` (`more_vendor.py:396-408`) reports that as "no push possible" instead of crashing.

**S3. Checkpoints of MORE arms are fingerprinted.** `eval_bestfirst.py` now passes the checkpoint of `more` and `more_eca` arms to `runtime_fingerprints`, so different seeds no longer share a run_id.

**S4. Rendering at the deploy scorer's convention.** The H5 renders states with `region_samples=None`, as every CS training builder does; this is shared with HY5U, not MORE-specific.
